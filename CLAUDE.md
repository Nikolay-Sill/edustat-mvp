# EduStat MVP

Прототип ИС аналитики успеваемости обучающихся. Проект для портфолио системного аналитика:
сначала спроектирован (docs/specs), затем реализуется как MVP по собственной спецификации.

## Источники истины
- API: `docs/specs/edustat-openapi.yaml`. Пути, поля, коды ответов и формат ошибок (RFC 7807) должны совпадать со спецификацией.
- Модель данных: `db/migrations/` (V1 — по ER-диаграмме, V2 — дополнения MVP). Схему меняй только новой миграцией V3, V4…
- Требования и сценарии: `docs/specs/EduStat_проектная_документация.pdf` (FR — Таблица 3.1, US — раздел 3.2, статусы случая риска — Таблица 4.2).
- Если реализация требует отступить от спецификации — сначала спроси, затем запиши отклонение в `docs/deviations.md` (что, почему, какое FR затронуто).

## План работ
- `ROADMAP.md` — задачи по этапам. Работай только над задачами текущего этапа, который я назову.
- Выполненные задачи отмечай `[x]` в ROADMAP.md в том же коммите.
- Не делай то, что перечислено в разделе «Вне MVP».

## Стек и соглашения
- Python 3.12, FastAPI, SQLAlchemy 2, PostgreSQL 16 (docker-compose), pytest. Без Kafka, Kubernetes, микросервисов.
- Модули backend/app: core, auth, academic, integration, analytics, risk_cases, notifications, reporting.
- Каждое FR покрывается тестом; в docstring теста указывай ID требования (например, `FR-12, US-01`).
- Комментарии в коде и сообщения коммитов — на русском.
- Один этап = одна ветка `stage-N-<тема>` и один pull request в main.

## Как со мной работать
- Я учусь: после каждой задачи коротко объясняй, что сделано и почему так.
- Перед крупными изменениями показывай план.
- Не коммить данные OULAD, `.env`, обученные модели.
